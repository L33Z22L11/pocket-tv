# 构建与实现

首次使用请看 [README](../README.md)。以下命令均在仓库根目录执行。当前版本为 1.1.0 / PTV6，需配套固件与电脑程序。

## 国内电视 TUI 与 Wi-Fi

宽窗口采用三栏：左侧搜索与频道列表，中间播放状态与完整频道信息，右侧设备状态与日志；常用操作保留在底部一排按钮，收藏、换台、配网等使用可点击的底栏提示。窄窗口自动改为可滚动布局；长名称在信息栏完整换行显示。

运行 `./tv.sh` / `tv.cmd`。默认读取 [vbskycn/iptv](https://github.com/vbskycn/iptv) 的国内 IPv4 列表，可切换 IPv6、iptv-org 中国或输入自己的 M3U 地址/文件。IPv6 源要求电脑网络能访问 IPv6，设备仍接收电脑转换后的画面。

- 搜索频道名称或分组，按分组筛选；方向键选择，回车播放。
- `F` 收藏，点击“只看收藏”筛选；刷新失败时使用最近成功缓存。
- 空格启停，`N`/`P` 换台，`+`/`-` 调音量，`H` 开关设备帮助。
- `Ctrl+F` 搜索，`F5` 刷新，`Ctrl+Q` 停止播放并退出。输入框内按键用于输入。
- “测首帧”实际尝试解码当前频道，最多等待约 20 秒；结果不保证长期可用。
- 右侧显示频道、音量、传输方式及音频缓冲状态。配网会先停止播放器，避免抢占串口。

按 `W` 或点击底栏“配网”，设备通过 USB 扫描附近的 2.4 GHz 网络；从列表选择网络并输入密码，也可点击“手动输入”填写隐藏网络。扫描与连接过程中按钮会显示进度并整块高亮。也可运行 `./wifi.sh` / `wifi.cmd` 交互配网。换台会立即取消旧节目的等待，慢源仍需下载并缓冲，界面会显示“切换中 / 缓冲中”。随后重新播放，USB 优先；断开 USB 数据连接后尝试 Wi-Fi，重新插入 USB 后切回。**拔线后设备须仍有电，电脑播放器也须持续运行。** 切换会重新缓冲，暂不保证无缝。配对模式保留主机解码进度；未配网的 USB 单通道重连仍会重开本地文件。

设备与电脑需要网络互通。访客隔离、门户登录和企业 Wi-Fi 不支持；使用可信局域网。配对密钥通过 USB 设置，TCP 使用双向挑战认证，但媒体数据未加密。设备保存 Wi-Fi 凭据，电脑仅保存配对密钥、设备 ID 和地址，默认 `~/.config/pocket-tv/device.json`（POSIX 权限 0600；Windows 继承目录权限）。不要分享该文件。

网络使用 TCP 5760 和 UDP 5761；广播发现受阻时运行 `./tv.sh --wifi-host 设备IP` 或 `./play.sh --wifi-host 设备IP 视频路径`，仍需事先 USB 配对。`./wifi.sh --status` 查询，`./wifi.sh --forget` 清除配网；`./play.sh --usb-only ...` 强制 USB。

为给 Wi-Fi 留出内存，本版改用 32 KiB 解压窗口、底部文字区域缓存及 30 行 DMA 条带，单帧数据上限 32 KiB；高噪声画面会自动减少调色板颜色以适配上限。音频仍为 16 kHz、16 位、单声道 PCM（32 KB/s），保留 512 ms 缓冲。无线吞吐、持续帧率和切换时长需真机实测。

## 播放

需要 Python 3.10–3.13 和 USB 数据线。macOS/Linux 使用 `./play.sh`，Windows 使用 `play.cmd`；首次启动自动创建虚拟环境并安装依赖。PyAV 自带 FFmpeg 解码库，播放不需要另装 ffmpeg 命令。

```sh
./play.sh /path/to/movie.mp4
./play.sh /path/to/videos
./play.sh 'https://example.com/live/index.m3u8'
./play.sh --preset china --list
./play.sh --preset china --search CCTV
./play.sh /path/to/channels.m3u
```

设备重启或拔插 USB 后，脚本保持运行并自动重连，按 USB 设备序列号重新寻找串口（串口名称变化也支持），恢复断连前的频道与播放/暂停状态，音量从设备记忆恢复。网络直播重新缓冲后继续播放；本地文件会从头播放。设备尚未插入时也可先启动脚本等待。

不传路径时读取 `media/`。多个 USB 设备时加 `--port /dev/cu.usbmodem1101`（Windows 例如 `--port COM3`）。`--seconds 10` 限时播放；`--inspect --seconds 3` 只验证解码，不连接设备或输出声音。

竖屏时短按 ↑/↓ 增加/降低音量，横屏时方向对调（每次 5，范围 0–100）；竖屏时长按 ↑/↓ 约 1.5 秒切换上一项/下一项，横屏时仍为 ↑ 上一项、↓ 下一项。短按 OK 暂停/继续，长按 OK 约 1.5 秒显示/隐藏中央帮助；音量保存在设备中，帮助不跨重启保留。终端输入 `+`/`-` 调音量、`p`/`n` 换台、空行启停、`h` 开关帮助、`q` 退出，均需回车。长按换台不会同时调音量。本地视频结束后顺序循环，直播源失效后延迟重试或切换下一项。

**音量保存在设备 NVS 中，重启和主机重连后恢复上次设置。** 首次使用默认 0；短按 ↑/↓ 调整后立即保存，降到 0 即无声。退出程序或 USB 通信中断会停止声音，但不会把记忆音量清零。不设独立静音开关。固件和主机协议为 PTV6，需配套使用。

音频为 16 kHz 单声道，由独立任务连续输出。设备保留 512 毫秒 PCM 缓冲，主机提前约 450 毫秒发送音频；有声直播启动或音频断流后先累计约 2 秒 PCM，再按约 1 秒预播放延迟恢复，音画分别调度；画面迟到可丢帧，音频不会因此丢包。网络长时间断流仍可能停顿，日志中的 `audio_underruns` 和 `audio_write_errors` 用于区分缓冲断粮与输出错误。

普通 MPEG-TS HLS 直播由电脑四路并行下载，首段边下载边解码，不再等待两个完整分段。最多缓存 8 段、每段上限 8 MiB，内存在电脑上使用。音频仍先累计约 2 秒，期间尽早显示首帧。加密、独立音轨、fMP4 和字节范围清单保留原生路径；“测首帧”和 `--inspect` 使用直接读取，因此检测时间不等于实际起播时间。降低等待后，慢线路仍可能需要重新缓冲，不能保证秒开或持续不卡。

设备在画面中央用中文白字和半透明黑底显示“加载中”“缓冲中”“重新连接”“暂无信号”，暂停时显示“已暂停”。长按 OK 显示/隐藏中文帮助；关闭帮助后恢复当前暂停或加载状态。正常播放不再常驻旧 HUD。TUI 默认采用 Catppuccin Mocha，并显示加载阶段和等待时间。


自动适配横竖屏并等比缩放，不为提示压缩视频区域。调音量时显示 `VOL`、20 段亮/半亮音量条及数字，约 1.8 秒后消失；换台时左下角显示文字台标，首帧到达后约 4 秒收起。所有提示使用半透明黑底，消失时从索引缓存恢复原画面，暂停时也可操作。字体为 Fusion Pixel 简体 12px 的烤制子集（汉字笔画 11×11），3,874 字形约占 102 KiB Flash；少数字库不含的字用横线占位。默认目标 20 fps，落后时丢帧追赶。

## IPTV 来源

预设 `iptv-org` 为 [iptv-org/iptv](https://github.com/iptv-org/iptv) 的全球列表，`china` 为其中国地区列表；`free-tv` 为 [Free-TV/IPTV](https://github.com/Free-TV/IPTV)。可先 `--list` 查看，再用 `--search` 按名称或分组筛选。公共频道可用性随来源和网络变化，不保证每条都可播放。

HLS 清单作为一个视频源处理；IPTV 清单中的频道作为多个可翻页项目。支持相对地址与 VLC 风格的 User-Agent/Referer 字段。

## 固件

适配此项目的 AI Passport 引脚和 8 MB Flash。ESP-IDF 5.5.3：

```sh
. ~/esp/esp-idf/export.sh
cd firmware
IDF_COMPONENT_MANAGER=0 idf.py build
idf.py -p /dev/cu.usbmodem1101 flash
```

应用输出 `pocket-tv.bin`；当前本版的完整镜像为 `firmware/build/pocket-tv-full.bin`，从地址 `0x0` 安装；`releases/v1.0.0` 保留旧版发布文件。完整镜像可用 `IDF_COMPONENT_MANAGER=0 idf.py build merge-bin -o pocket-tv-full.bin` 重新生成。分区保持原厂 Recovery 和设备标识区域，保留上电长按 UP 5 秒进入 Recovery 的引导钩子。烧录替换应用和引导程序，不执行整片擦除。

## 实现

PyAV 在线解码 → 旋转/缩放 → 256 色调色板和 zlib 索引帧 → USB Serial/JTAG 或局域网 TCP → ESP32-C3 解压 → RGB565 SPI DMA 显示。解码队列有界，设备共享一个 32 KiB 接收缓冲、流式解压和双 DMA 条带缓冲，通过 CRC 校验和播放代次拒绝损坏或过期帧。无需将整段视频存入设备，也不支持脱离电脑独立播放或蓝牙视频流。

运行 `firmware/tools/validate.sh --static` 做主机和协议测试；`tools/hardware_smoke.py PORT` 使用纯色帧及静音 PCM 检查真机协议、横竖屏和按键状态转换。它不代替实际按实体键与观察屏幕。

## CCTV 试播

运行 `./cctv.sh`（Windows：`cctv.cmd`）播放已筛选的 `config/cctv.m3u`。目前为 CCTV+ 1/2，两路均已在本机解码验证；它们不是 CCTV-1/2 综合台/财经台。来源与探测结果见 `config/cctv-source.md`。
